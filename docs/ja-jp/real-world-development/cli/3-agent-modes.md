最初に小さな機能をプロジェクトに追加しました。より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot CLI は組織の既存のワークフローに沿って動作し、適切なものを適切な方法で構築できるようにします。このレッスンから、エージェントを使った一般的な開発プロセスをいくつかのレッスンにわたって進めます。issue から新機能を作成し、コードの妥当性と機能の動作を確認して、最後にプロジェクトへマージします。

> [!NOTE]
> 機能開発のワークフローでは、同じ会話とブランチを使い続けます。通常はファイルの種類ごとにブランチや PR を分けますが、ここでは重要な概念に集中できるよう簡略化しています。

このレッスンでは、次のことを行います。

- GitHub issue から Copilot との新しい会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP 検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが拡大しているため、訪問者がカテゴリや発行元でゲームを絞り込めるようにします。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細があります。Plan モードで決定し、範囲を定めた実装を Autopilot に任せます。

## 背景

AI コーディング エージェントを開発ワークフローに導入しても、基本は変わりません。むしろ、さらに重要になります。多くの開発者は次のような流れで作業します。

1. 実装内容を説明する issue から始めます。
2. 構築するものの計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、多くの場合、上記の流れを応用したものです。

この標準的な方法に従うことで、AI が生成したコードが要件を満たし、手動で書いたコードと同じ確認プロセスを通るようにします。

## 会話モード

**会話モード**は、エージェントにどれほどの自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: ユーザーとエージェントが協力します。エージェントは変更を提案し、次に進む前にユーザーの入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。プロジェクト ファイルの編集はできません。
- **Autopilot**: エージェントがコードを書き、テストを実行し、タスクの完了まで自律的に反復します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue から始める

フィルタリングに取り組む前に Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止している場合は再起動します。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が表示されます。`#` を使うと、GitHub の issue またはプルリクエスト (PR) をコンテキストに追加できます。

## フィルタリング機能を計画する

計画を立てると、Copilot に作業を任せる前に機能の実装方針やタスクの進め方を決められます。複雑な作業を始める前に計画を立てると効果的です。Plan モードに切り替えて、計画の作成を Copilot に依頼しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下に **Plan** と表示されていることを確認します。
2. 前の手順で追加した issue 参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調査し、最適な方法を検討して計画を作成します。

3. フィルタリングの動作について質問された場合は、希望する方法で回答します。どの答えも間違いではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して展開します。
5. 上下にスクロールして計画を確認します。
6. 決定した内容と異なる箇所があれば、修正を依頼します。

## Autopilot を承認する

計画を作成して確認したので、実装を始めます。Autopilot モードを使って Copilot に作業を任せましょう。Autopilot は、タスクが完了したと判断するまで問題に取り組み続けます。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みバージョンで同様のラベルが付いた選択肢を選びます。
2. プロンプトの下に **Autopilot** と表示されていることを確認します。
3. Copilot が合意した計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まることがあります。先に計画を確認してください。依存関係がない場合やポートが競合する場合は、チェックを完了と見なす前に環境の問題を解決します。

## 実装をレビューして検証する

他のコードと同様に、生成されたコードもマージ前にレビューする必要があります。コードを確認し、サイトを実行して問題がないことを確かめましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** や **Autopilot** でないことを確認します。
2. `/diff` を入力して、フィルタリングの実装とテストを調べます。
3. 結果を issue と計画時の決定事項と比較します。
4. コードのレビュー後に <kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新機能を試す

コードに問題がなくても、実際に動作するか確認しましょう。前と同じようにアプリを起動し、Codespaces で転送されたポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces からポート `4321` が利用可能になったと通知されたら、**Open in Browser** を選択します。
3. 計画で合意したカテゴリ フィルター、発行元フィルター、その組み合わせを試します。
4. リセット時と結果がない場合の動作が、issue と決定事項に沿っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

会話モードを使い分けて機能を構築し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub issue から Copilot との新しい会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動検証しました。
