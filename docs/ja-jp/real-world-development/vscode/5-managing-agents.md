GitHub Copilot をエージェント モードにすると、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、自分のマシンでリアルタイムに行われるすべてのツール呼び出しとファイル編集を確認できます。差分をインラインでレビューし、個々の変更を受け入れたり拒否したりできます。また、エディターを離れずに追加のプロンプトを送信し、会話を誘導して作業を改善、拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッションの途中でエージェントを誘導し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加のリクエストがありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいとのことです。新たに会話を始めるのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調べたファイル、実行したコマンド、提案した編集を確認できます。各ファイル編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択すると変更を受け入れます。
    - **Undo** を選択すると変更を元に戻し、エージェントに再度取り組ませます。
4. チャットの上部にある **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行など、ツール呼び出しに許可が必要な場合、エージェントは一時停止して **Allow** のプロンプトを表示します。問題ないコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。変更内容の概要が最後に表示されます。

## ライト モードを追加するようエージェントを誘導する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けることで、エージェントはこれまでの作業、つまり編集したコンポーネント、スタイルの方法、ローカル ストレージのパターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはすでに加えた変更を調べ、ライト モードの追加を提案します。
3. ハイ コントラスト モードのときと同様に、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. たとえば、気に入らない方法でトグル UI をリファクタリングするなど、エージェントの作業が意図と異なる場合は、チャット入力欄の横にある **Stop** ボタンで停止してから、追加の指示を送ります。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すよりもすばやく作業できます。追加プロンプトを使って、「CSS を簡潔にして、セレクターを重複させず CSS 変数を使ってください」のような調整、「3 つ目のトグルは追加せず、既存の設定パネルにライト モードを統合してください」のような軌道修正、「両方の切り替えにキーボード ショートカットも追加してください」のような範囲の拡張を依頼できます。

## 作業セットを確認する

変更をコミットする前に、エージェントが編集したすべての内容を簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更ファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. いくつかの変更ファイルを開いて差分を確認します。カスタム エージェントが示したアクセシビリティのパターン、つまり ARIA 属性、キーボード ナビゲーション、セマンティック HTML、ローカル ストレージによる設定の保持が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、進行中のセッションを監視して誘導しました。各ファイル編集を確認し、変更を受け入れるか拒否し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視します。
- 個々のファイル編集を受け入れる、または拒否します。
- 追加プロンプトを使って進行中のセッションを誘導します。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボ全体でローカルのカスタム エージェントが行った変更を確認します。
